## 风格校准维度（以本书风格指南与样章为准）

审校前先读 `bible/style-guide.md` 与 `AGENTS.md`「本书口径」指定的校准样章，逐项确认本书的“正常读感”坐标，**绝不拿另一类文风的偏好硬套本书** `[模型]`：

| 校准维度 | 审校时核对的问题 |
|---|---|
| 1. 句式与段落长度 | 本书偏短句断句还是中长句流动？单段上限几行？是否常用单句成段制造呼吸感？ |
| 2. 标志性标点习惯 | 破折号、省略号、感叹号的使用频率与禁区是什么？ |
| 3. 场景切换与锚定 | 场景转换是否一律用 `---`（[SB §7.2](formats/chapter.md)）跳跃省略无用赶路？新场景开头怎样锚定时间与空间？ |
| 4. 对话密度与修饰 | 本书对话偏极简实务还是机锋密集？是否禁用副词修饰“说”？连续对话几轮插动作？ |
| 5. 描写与比喻取材 | 描写偏白描具象还是偏浓墨氛围？比喻取材于日常、职业专业还是诗意传统？ |
| 6. 情绪与留白策略 | 情绪靠生理/动作克制表达，还是允许直接抒情？重大时刻是留白还是铺陈？ |
| 7. 叙事视角与距离 | 严格第三人称有限视角、第一人称还是多视角？旁白是否带克制冷幽默？章末是否允许短暂全知切换？ |
| 8. 本书禁止清单 | 本书明确禁止哪些套话、标点、元信息或特定写法（如精确日期、emoji、过长内心戏）？ |

- 若项目尚未建立 `bible/style-guide.md`，提示作者可用 `fiction-craft` 生成一份；当前先以作者指定的校准样章或最近 1–2 章定稿作为临时基准，并在报告中注明 `[作者]`。

## 常见失手点（“报告腔”高发症状）

中长篇连载写到后段，最容易反复出现以下八类失手点，精查时优先排查 `[模型]`：

1. **先给判断，再补场景**：开头先抛一句抽象结论（“这里的秩序很微妙”），后面才把人、物、地点端出来。
2. **场尾再补一层意义**：场景动作已经把意思做足了，段尾还要画蛇添足补一句“所以这意味着……”。
3. **同一套原则反复重说**：同一卷里每章都在换着话讲同一条世界观原则，把活规矩喊成了口号。
4. **用“记录行为”替代戏剧落点**：高频用“他记进笔记 / 拍了张照 / 存了档 / 写下摘要”收尾，把小说写成调研日志。
5. **人物替作者发结论**：对话像专题访谈或行业复盘，不像当事人在现场说话。
6. **正文混入内部写作视角**：出现“本章”“伏笔”“支线”或内部文档名、ID 等元信息（脚本先扫 `internal-ref` / `internal-term`，模型补查隐性元视角）。
7. **区域段缺乏结构锚点**：进到新区域只有见闻、风物与样本收集，没有本地引路人、主节点与贴合当地气质的麻烦。
8. **循环节奏失衡**：连续几章还在“熟悉环境”迟迟不进主节点；或者连出几章麻烦却没有可见结算与再出发。

## 蓝本审核八步法

### 第一步：开场审核（前三段）

- 划出本章开头前三段，检查是否先落到一个**具体物件、动作、地点或手头任务** `[模型]`。
- 若前三段先给抽象判断、再找场景落地，直接调换叙事顺序：先给读者可见之物，再出人物短判断 `[模型]`。
- 开头如果出现对照或比较，必须服务眼前当下判断，不先抛宏观结论 `[模型]`。

### 第二步：篇幅审核（字数区间）

- 对照 `length.mjs` 的逐章状态与 `.fiction/config.json` 的 `length.min`、`length.soft_max`（[SB §8](formats/config.md)） `[脚本]`：
  - **低于 `min`（`SHORT`）**：硬规则不通过。仅审不改时报告偏短及建议补足方向；获授权修稿时须先补足再细修，只能补四类有效内容——有信息增量的动作、有代价感的现场细节、有分寸变化的人物互动、对后续行动真正有用的物件/单据/场面细节，禁止补空结论 `[模型]`。
  - **高于 `soft_max`（`LONG`）**：脚本仅提示偏长（退出码仍为 `0`），由模型判断是不是把两章职责塞进了一章；优先迁移或合并可前移/后移的说明段、砍掉重复收束与报告腔，**绝不砍掉有效场景** `[模型]`。

### 第三步：区域循环审核（采用区域循环时）

若当前卷或阶段采用了 `fiction-planner` 的区域循环结构，核对以下四点：

1. 本章推进了区域循环的哪一步（进入限制 / 引路人 / 小任务 / 主节点 / 连锁任务 / 区域麻烦 / 收口留线 / 结算再出发）？ `[模型]`
2. 本章具体坐实了“引路人、主节点、区域麻烦、可见结算收益”四项中的哪一项？答不清多半是“逛到哪写到哪” `[模型]`。
3. 检查单项质量：引路人须可信但有限（不兼任外挂与全能兜底）；主节点须能反复回返；区域麻烦须贴合当地气质（不每站都换皮成“抢东西”）；结算收益必须可见，至少落到物、人、规矩、判断中的一类，而非一句抽象感悟 `[模型]`。
4. 若一章同时硬塞三步以上，通常说明职责过满，应提醒作者考虑拆分 `[作者]`。

### 第四步：总结句审核

- 结合 `lint.mjs` 的 `SUM01–SUM13` 命中结果（详见 `lint.mjs --help`），并在全文人工补搜同义总结句式与“记录替代落点”句式 `[脚本]` + `[模型]`：
  - 典型检索词：`这就是`、`问题不在`、`值钱的是`、`这就够了`、`真正……的是`、`显然不是`、`这很重要/现实/关键`、`真正的意义在于`、`说到底 / 归根到底`、`值不值 / 小不小气`、`他/她终于明白/意识到/懂得了`、`这意味着 / 说明`、`某种意义/程度上`，以及“记进笔记 / 存下摘要 / 写进私档”。
- 每找到一句，连问两遍：
  1. 这句话表达的意思，前面的场景动作是不是已经做出来了？
  2. 如果整句删掉，读者会不会照样懂？
- 答案是“会”的，能删就删，需要保留倾向的并进一个可见动作里 `[模型]`。

### 第五步：信息分层审核

- 检查同一信息有没有在两个场景里完整复读 `[模型]`。
- 若背景信息已在路上、私下或前文铺垫过，正式场景只保留执行层、边界与触发条件 `[模型]`。
- 解释只说到“当下够用”，不把整套体系一口气讲完；场景已经演清楚的，旁白不再补完整讲解 `[模型]`。

### 第六步：人物口气审核

- 逐句复核本章关键对话：这是角色在现场会说的，还是作者为了交代设定硬塞的 `[模型]`？
- 若偏后者，用三种手法之一改写：
  1. 让另一名有动机的角色主动发问；
  2. 把半句解释转成角色的一个具体动作或物件操作；
  3. 删掉台词说明，改为视角人物在当下作一句贴着物件的短判断 `[模型]`。

### 第七步：章尾审核（最后五段）

- 单独通读本章最后五段 `[模型]`。
- 风险与秩序感优先从具体征兆长出来（人群站位、视线停留、价格或供货异动、单据缺项、责任链断口、普通人被卷入的一瞬），不要在章尾靠主角总结秩序原则 `[模型]`。
- 若章尾主要靠“记一句 / 拍张照 / 写摘要 / 存私档 / 心里暗想”收束（连续使用极易写成报告），优先改写为以下四种具象前推力之一 `[模型]`：
  1. **外部新信号**：一条打破预期的消息、门外异动、突然亮起的灯或意外来人。
  2. **物件被重新分类**：原本普通的旧物突然显出新用途或危险含义（例：林砚把旧钥匙翻过来，才发现齿槽里卡着一层新刮下的蓝漆）。
  3. **路径被明确选择或放弃**：主角做出不可逆或有代价的决定，行动已经迈出半步。
  4. **风险向前擦近半步**：原本停在远处的麻烦，真正擦到了身边人、手头物或眼前的规矩线上。
- 过渡章允许阶段性收束，但收束后仍须留下一个具体的前推进力（对应 [SB §7.2](formats/chapter.md) 钩子分级） `[模型]`。

### 第八步：跨章复核（相邻三章）

批量审校或每写满 3 章时，连读相邻三章正文（可配合 `chapters/{vol}/summary.md`），检查以下八项：

1. **章尾同质化**：相邻三章是否连续复用同一种收束方式（如连着三章都是“看手机消息”或“回家记一笔”）？ `[模型]`
2. **边界兑现**：如果连续两章都在“讲边界 / 讲规矩”，第三章必须让边界在具体事件里兑现 `[模型]`。
3. **风险落地**：如果连续两章都在“谈风险 / 铺威胁”，第三章必须让风险真正擦到普通人、关键人物或具体物事上 `[模型]`。
4. **原则复读**：是否连续多章反复喊同一句核心原则或口号？ `[模型]`
5. **区域循环节奏**（如采用）：连续三章都还在“进入 / 熟悉环境”却未触及主节点或区域麻烦 → 节奏过慢；连续三章都在“出麻烦 / 收口”却没有结算与再出发 → 循环失衡 `[模型]`。
6. **情绪波形与爽点节拍**：相邻章节是否形成“紧 → 松 → 更紧”的波浪（避免连着两章都是满格高潮或都是平缓低谷）？对照 `config.rhythm.beat_every` 与 `config.rhythm.external_event_max_gap`（[SB §8](formats/config.md)）核对密度 `[模型]`。
7. **日更与爆更钩子排布**：结合 `outline.md` 的 `## 日更位置`（[SB §7.3](formats/chapter.md)）与 `config.daily.last_hook_min`（日常末章下限）或 `config.daily.burst.last_hook_min`（爆更期末章下限，见 [SB §8](formats/config.md)）核对钩子强弱，最终排期由作者确认 `[作者]`。
8. **套路重复**：同一种写法跨章反复出现，读者开始提前猜到结果。第 1 项章尾同质化、第 4 项原则复读也归这一组，按下方门槛定级 `[模型]`。

#### 套路重复：查什么、何时豁免、怎么定级

常见模式（相邻章或同一阶段内反复出现才算）：

| 模式 | 典型表现 |
|---|---|
| 章尾同质化 | 连续几章用同一种收束：看手机消息、回家记一笔、门外有人敲门 |
| 原则复读 | 同一条核心原则或口号换着说法每章喊一遍 |
| 破局手段同质 | 几次危机的解法是同一种外力：总有熟人恰好路过替主角撑腰、要找的东西恰好自己冒出来，或对手不付任何代价就把底细说漏 |
| 对抗无筹码交换 | 冲突只在原地加码：你逼一句我顶一句，越说越冲，谁手里的东西都没易手 |
| 固定微动作与机械对仗 | 同一个小动作反复挂在台词后面，几章下来成了标点；叙述高频工整对仗 |
| 动作已说明后补总结 | 场景已经演清楚，段尾或章尾固定补一句总结；跨章成了习惯（单章内的同类问题见第四步） |
| 收尾关死悬念 | 章尾把刚抛出的问题当场答完，或用一句定论把下文收死 |
| 节奏平均 | 连续几章的起伏配比一模一样，没有紧松变化（与第 6 项情绪波形同查，只记一处） |

注意区分：一句利落、钩向下文的收尾句（落在新动作或新疑问上）是优点，不报。

**豁免（不报）**：为反讽或宿命感刻意安排的呼应（誓言、仪式、口头禅回环）；每次都有升级的系列笑点；人物档案里写明的标志性小动作；同一危机链上相邻章沿用同型章尾；全书统一的章首或面板格式；一次性出现的题材惯用桥段。拿不准是否故意，记备注问作者。

**判定门槛**：至少给出两处具体位置（章号 + 段落或场景），并说明它削弱了什么（结果可猜、张力被提前泄掉、读者疲劳）。只写“有 AI 味”“套路化”而没有位置与影响的，不成立，不报。

**定级**：属技法默认，最高记“次要”。若重复同时违反了已立事实或因果（例如无解释抹掉前文立下的伤势、欠债或身份暴露；冲突吵完人物处境毫无变化却当成已解决；反转没有任何前文事实支撑），改按审定约束记“重要”，一次即可，不再当套路问题另记。

**修复口径**：只指出哪几处撞车、读者为什么能猜到结果，以及可换用的方向（已有关系、已埋证据、升级的代价）；审校不代开新桥段，不代写台词，具体改法回到 `fiction-chapter` 或交作者。局部修补撞车处，不要求整章重写。

## 回修后十问速查

每章回修完成、准备宣布通过前，快速过一遍下面十问：

1. `length.mjs` 的逐章状态是否达到 `min`（非仅看退出码）？ `[脚本]`
2. 若 `length.mjs` 提示 `LONG`，是否已核实并非职责过满或重复说明堆积？ `[模型]`
3. 开头前三段是不是先有可见之物、动作或地点？ `[模型]`
4. 本章最重要的信息，是不是通过场景动作长出来的，而不是靠作者讲出来的？ `[模型]`
5. 若属区域推进卷，本章坐实了区域循环的哪一步，留下了什么可见收益？ `[模型]`
6. 有没有作者替主角多说一句总结或哲理？ `[模型]`
7. 有没有把世界规则或人物原则喊成口号？ `[模型]`
8. 关键对话是不是角色在现场会说的话？ `[模型]`
9. 有没有复用上一章同一种章尾？ `[模型]`
10. 章尾留下的是具体前推力，还是“记一笔 / 悟道理”？ `[模型]`
