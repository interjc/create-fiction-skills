# 题材包使用与编写指南

> 题材包（Genre Pack）是 `fiction-craft` 提供的题材知识插件，把不同网文与竖屏短剧题材的读者期待、爽点语法、结构节奏、体系规则、雷区和工具链接口沉淀为可复用参考。

## 什么是题材包

套件将写作知识分为三层，覆盖优先级从高到低依次为：

1. **项目口径**（作者项目 `AGENTS.md`「本书口径」、`bible/style-guide.md`、`.fiction/config.json`）：只属于当前这一本书的设定、视角、人设禁区与数值阈值。
2. **题材包**（本目录 `references/genres/<id>.md`）：某一题材通用的读者预期、爽点结构、体系边界、常见雷区与默认配置建议。
3. **通用内核**（`fiction-craft` 顶层参考文档、`fiction-continuity` 等）：跨题材通用的场景五要素、信息分层、对话节奏与伏笔管理方法。

题材包不替代你的书内设定，而是把“这个题材写长容易塌在哪里、读者到底来买什么单”提前摊在桌面上，减少从零摸索的试错成本。

## 各 Skill 如何使用题材包

作者在 `.fiction/config.json` 的 `book.genres` 中填入一个或多个题材 ID（例如 `["xianxia"]` 或 `["suspense", "urban"]`）后，各 skill 按各自职责按需读取对应文件：

| Skill | 优先读取的节 | 具体用途 |
|---|---|---|
| `fiction-init` | `与套件的接口` | 建书时提醒重点启用的 `bible/` 文件，引导作者设置 `config.json` 阈值、脱敏词表与禁用套话 |
| `fiction-planner` | `读者期待`、`核心爽点`、`常见结构与节奏`、`体系设计要点`、`人物配置`、`钩子素材` | 辅助创意定位与黄金三章设计，为全书/卷纲填充 `volumes/{vol}.md` 规划表的 `爽点` 与 `钩子` 列，调整 `rhythm.beat_every` |
| `fiction-chapter` / `fiction-craft` | `核心爽点`、`体系设计要点`、`人物配置`、`钩子素材` | 起草 `outline.md` 与 `v{n}.md` 时，把抽象爽点落成具体动作、信息差与代价约束，选定章末钩子类型 |
| `fiction-review` | `常见雷区`、`核心爽点`、`与套件的接口` | 审校正文与复盘整卷时，排查题材高频硬伤（如战力通胀、机械降神、工业糖精），并补充 `.fiction/lint-patterns.txt` |
| `fiction-short-drama` | `短剧改编要点`、`钩子素材` | 编写 `drama/{series}/series.md` 与 `adaptation-map.md` 时，判断视觉锚点保留、慢热戏删改与前 3 秒/付费卡点位置 |

### 读取与降级规则

- **按配置加载**：只读取 `.fiction/config.json` 中 `book.genres` 列出的题材包，不把未选用的题材塞进上下文。
- **未配置时的降级**：如果 `book.genres` 为空或所需 `<id>.md` 尚未编写，各 skill 照常按通用内核运行，不阻断写作流程。
- **格式摘录优先**：写入或调整任何项目结构、主写入口注册表与权威分层前，先打开对应格式摘录（本目录层级引用 `[SB §1–§5](../formats/project.md)`），不凭记忆臆造格式。
- **冲突裁决**：当题材包建议与作者项目的 `AGENTS.md`「本书口径」或 `bible/canon.md` 冲突时，一律以项目自身设定为准（[SB §3](../formats/project.md)）。

### 卷纲与章纲字段联动

- `volumes/{vol}.md` 章节规划表中，**`爽点` 列**只填爽点类型名（如`越阶反制`、`物证拆穿`），**`钩子` 列**只填单一等级字母（`S` / `A` / `B` / `C`），不要把爽点名与钩子等级拼写在同一单元格里。
- `chapters/{vol}/{ch}/outline.md` 的 `## 爽点` 与 `## 钩子`：写章前对照题材包核对最小铺垫章数、钩子落点说明与防崩坏清单，确保爽点落地前已有足够前置信息。

例如，某本书在 `.fiction/config.json` 中配置了双题材，并在 `AGENTS.md`「本书口径」拍板以悬疑为主、都市为辅：

```json
{
  "book": {
    "title": "夜班值守日志",
    "genres": ["suspense", "urban"]
  }
}
```

各 skill 会按项目口径以悬疑作为核心结构与反转基准，同时借用都市的现代职场规则、脱敏清单与生活流质感。

## 如何选用与混搭题材

网文常见“主题材 + 副题材”双拼。混搭时**主副关系完全由作者在项目 `AGENTS.md`「本书口径」里拍板**；把主题材排在 `book.genres` 列表首位只是便于阅读的可选约定，不是套件强制规则：

1. **主题材定结构与兑现**：由作者指定的主题材，决定全书的卷级弧线、章末钩子重心和读者最终买单的核心回报。
2. **副题材定环境与表皮**：副题材负责提供社会规则、行业细节、对话质感或辅助风味，不抢占主题材的高潮位置。
3. **冲突时主题材优先**：当副题材的习惯拖慢主题材节奏时，立即为副题材做减法。

| 常见混搭（`book.genres`） | 主题材负责什么 | 副题材负责什么 | 常见冲突与止损线 |
|---|---|---|---|
| `["xianxia", "scifi"]` | 境界攀升、资源争夺、因果清算 | 用工程实验、参数与故障思维写阵法炼器 | 忌写成纯科教论文；所有推导必须落回破局与斗法 |
| `["suspense", "urban"]` | 线索公平、时间线核对、反转闭环 | 职场权责、监控/资金流水、烟火气配角 | 忌职场发泄压过解谜；每次冲突必须产出实证 |
| `["romance", "history"]` | 双向拉扯、偏爱兑现、关系阶梯 | 礼法门第阻力、朝堂/宗族利害约束 | 忌权谋线把两人隔开十几章不见面 |
| `["history", "urban"]` | 古代制度与生产力制约、实务破局 | 现代管理/财务/物流思维转化为古代土法 | 忌直接照搬现代网词或无视古代产业链 |

## 新增题材包模板

如果你的题材不在上表（如游戏竞技、末世废土、民俗志怪、西幻冒险等），可在本目录新建 `<genre-id>.md`（小写字母与短横线命名），并将 `<genre-id>` 写入项目 `.fiction/config.json` 的 `book.genres`。

新增题材包必须保留下方 **全部 9 个二级标题** 且标题文字完全一致，确保各 skill 按标题定位时不会漏项：

```markdown
# <中文题材名>（<细分方向>）

> 题材 ID：`<genre-id>`。核心叙事契约：一句话说清读者买单的核心体验。

## 读者期待
- 列出 4 条读者打开这类作品最想获得的体验（以创作判断表述，不编造平台统计数字）。
- 附 1–2 条最容易导致读者弃书的“违约行为”。

## 核心爽点
- 说明 4–6 类高频爽点，每类附一句原创微型场景示例（写清压迫/预期与兑现动作）。
- 给出“爽点类型 → 适用章节权重（light/normal/heavy）→ 最小铺垫章数”的速查表。

## 常见结构与节奏
### 开篇切入（黄金三章）
- 2–3 种常见起手式，明确第一冲突与第一小回报的落点。
### 卷级弧线
- 一卷通常经历哪几个阶段，如何收束本卷并切入下一卷。
### 单章与日更节奏
- 单章内的情绪起伏，以及日常章与重头章在日更里的搭配方式。

## 体系设计要点
- 核心资源 / 能力 / 关系规则是什么。
- 代价、冷却、暴露风险与上限如何锁死。
- 升级阶梯、信息差控制与中后期防崩原则。

## 人物配置
- 主角定位、核心习惯与防工具人写法。
- 配角与对手配置表（角色位 / 常见套路 / 去脸谱写法 / 利益或情感锚）。

## 常见雷区
- 5–6 个高频硬伤与陈旧套路，每条附“问题表现 + 改法”。

## 钩子素材
- 按 `S` / `A` / `B` 钩子等级给出 5–6 种适配本题材章末的卡点模板与原创短例。

## 短剧改编要点
### 保留与放大
- 可直接转为竖屏画面、对峙台词或道具特写的元素。
### 必须删改
- 必须删砍或动作外化的慢热铺垫、心理独白与长篇背景说明。
### 前 3 秒抓手与卡点落位
- 给出“小说句 → 短剧动作/镜头”改写示范，以及开篇与付费卡点建议位置。

## 与套件的接口
### 核心 bible 文件
- 本题材最依赖的 bible 文件及填写重点（主写入口规则见 [SB §2](../formats/project.md)、[SB §5](../formats/project.md)）。
### `.fiction/config.json` 建议片段
- 按 `.fiction/config.json` 规范键名给出可直接参考的 JSON 片段。
### `.fiction/lint-patterns.txt` 建议片段
- 按 `fiction-review`（或 `fiction-chapter`、`fiction-init`）附带的 `lint.mjs --help` 说明的段头与模式语法，给出本题材高频套话或穿帮词检测片段。
```

## 维护约定

1. **篇幅控制**：每份题材包控制在 150–300 行之间，多用表格、清单与短例，少写大段空论。
2. **完全原创**：示例必须原创或借用中性日常场景，不搬运已出版作品情节，不触碰去书专属化词表。
3. **契约一致**：提到的文件名、主写入口、钩子等级（`S`/`A`/`B`/`C`）和模式语法必须与项目规范（[SB §1–§5](../formats/project.md) 及 `fiction-review`（或 `fiction-chapter`、`fiction-init`）附带的 `lint.mjs --help`）一致；同步在 `fiction-craft` 入口 `SKILL.md` 索引表中登记新文件。
4. **交付前自检清单**：
   - [ ] 仅本仓库贡献者：运行 `node tools/validate.mjs`，确认去书专属化词表与链接检查通过 `[脚本]`
   - [ ] 核对是否完整保留全部 9 个二级标题，且标题顺序与文字完全一致 `[模型]`
   - [ ] 核对读者期待部分以创作判断表述，没有编造平台数据或统计数字 `[模型]`
   - [ ] 核对核心爽点每类均附原创微型场景示例，且短剧要点兼顾保留项与删改项 `[模型]`
   - [ ] 核对配置键名与模式语法合法（对照 `fiction-review`（或 `fiction-chapter`、`fiction-init`）附带的 `lint.mjs --help`） `[模型]`
   - [ ] 确认该题材包与本书口径、混搭分工无冲突后再正式启用 `[作者]`
