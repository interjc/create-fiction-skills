# 网文章节写作

把已经确定的剧情方向写成一章正文，校对后把本章真正发生的变化记回故事档案。

## 何时用 / 不用

- 写新章、续写半章、按反馈修改未冻结正文：用本 skill。
- 改全书方向、重排卷纲、定爽点节拍、钩子级别或日更组合：交给 `fiction-planner`。`fiction-init` 只搭骨架，`fiction-planner` 定卷级计划，本 skill 按该计划写单章章纲并负责章后回写。没有规划 skill 时只执行已有卷纲；必须改规划时，交现状和待定项，等作者确认并同步卷规划再动正文。
- 只审不写，或要深查跨章矛盾、叙事与文风：交给 `fiction-review`。若仅请求深审而未安装，交现有稿件、待办和未做检查，不以轻审替代。
- 起草 `publish/blurb.md` 交 `fiction-planner`，审校交 `fiction-review`，对外提交交 `fiction-publish`；新书名确认后提醒作者核对配置的 `book.title`（[SB §8](references/formats/config.md)）。

缺下游 skill 时，交付已有文件、下一步待办及未做的检查，不代做其职责或报为已通过。

## 开始前

在作者的书根依次打开 `AGENTS.md`（尤其「本书口径」）、`.fiction/config.json`、`bible/sources.md`。写法以「本书口径」为先，其次是 `bible/style-guide.md`，最后才用本 skill 默认。`bible/sources.md` 登记每类信息的唯一维护文件（主写入口，见 [SB §5](references/formats/project.md)）；只在该入口写回，不让同一事实有两份独立维护的版本。

写入或修改任何机读文件前，先打开文末参考表里的对应格式摘录，照原文写，不凭印象。

缺项目骨架，提示先用 `fiction-init`；没装就请作者提供或补齐必要文件，不把猜测写成设定。仅缺配置时，脚本可用契约默认值，告知作者；若无法确认目标章是否已公开，不动已有稿。下列路径相对书根；从书根运行脚本，把命令中的占位符换成实际值，路径含空格时加引号。

作者只要试写一段或做到某一步时，按请求停下，说明还没走完哪些步骤，不把试写当整章回写。

## 六步流程

### 1. 核对上下文：先判断能不能写

确认章号与所属卷（[SB §2](references/formats/project.md)、[SB §7.5](references/formats/chapter.md)）。章号全书唯一、不补零；已有章按 `chapters/{vol}/{ch}/`，新章先查 `bible/volumes/{vol}.md` 的范围，再用 `chapters/{vol}/vol-info.md` 补查。卷归属有歧义就停下来问作者。**若章号落在 `frozen.ranges`，不动该章文件，不改写、不补句、不格式化、不新开稿**（[SB §7.1](references/formats/chapter.md)）。报告问题，建议在后续未冻结章补解释，或经作者拍板将读者口径记入 `bible/canon.md`；不倒改读者已见正文。

作者确认已有新章公开时，把章号交给 `fiction-init` 的「更新冻结清单」模式，不在写章流程里封存。没装 `fiction-init`，请作者两步处理：先在 `.fiction/config.json` 的 `frozen.ranges` 追加已确认的公开章（[SB §8](references/formats/config.md)），再从书根运行 `node <本 skill 目录>/scripts/lint.mjs --freeze`（[SB §4.2](references/formats/project.md)）。不要手改哈希或强制覆盖已有清单。

读卷摘要 `chapters/{vol}/vol-info.md`、详细卷规划 `bible/volumes/{vol}.md`、`bible/canon.md`，再运行：

```text
node <本 skill 目录>/scripts/brief.mjs <ch>
```

新章还没有目录，且卷范围尚未覆盖目标章时，卷号已经由作者确认才用 `node <本 skill 目录>/scripts/brief.mjs <ch> --vol <vol>`。这只指定简报读哪一卷，不代替补齐卷规划；若本章职责尚未定，先交 `fiction-planner` 或等作者确认。

简报是索引，不是资料全文。看本章规划、应埋／触／收的伏笔、逾期提醒、活跃支线、人物和时间锚点。生成成功仍可能有提醒：定位缺文件、解析错误或未登记人物；核心人物久未出场，先判断是否与本章职责有关，不硬塞。若章纲与已定卷规划冲突，不以简报的合并结果拍板；先核对卷规划，方向有变由作者决定。

打开上一章定稿的结尾（跨卷也按全书章号），确认最后一幕的地点、在场者、未完成的动作或悬念；简报只截尾，衔接不明就多读几段。确实是开篇时记「无上章」；本该有上章却缺稿时，不编造衔接。续写还要打开本章已有 `resources.md`、`outline.md` 与指定稿，定位停笔处。

按简报打开列出的主写文件和锚点，读相关原文而非扫遍 `bible/`；出场人物的稳定特征查 `bible/characters.md`，当前关系和状态查 `bible/character-dynamics.md`。只要时间移动（跳时、恢复、季节变化、期限逼近或事件换序），先查 `bible/timeline.md`，从上章时间点顺推或从期限倒推，核对所需时长、事件先后与窗口；内部用精确锚点，正文用相对时间。事实冲突或资料不足会改变剧情时，停下来请作者裁决。本步不写文件。

### 2. 摘 `resources.md`：只留本章要用的材料

把步骤 1 核实的材料摘到 `chapters/{vol}/{ch}/resources.md`。按 [SB §7.4](references/formats/chapter.md)：每条一行，末尾标来源 `（来源：相对路径#标题）`。首条写上章结尾（开篇则注明无上章并指向卷规划），次条写本章职责和写法边界。再摘本章真会用到的规则、当前人物关系、物品状态、读者已知和时间口径；别整页复制，也别把讨论稿当成已定事实。写作途中补读到必要资料时，把出处补回这里。无额外脚本；关键材料查不到，退回步骤 1。

### 3. 先定 `outline.md`：一章要改变什么

从 `resources.md`、卷规划和相邻章节定稿/章纲落笔，写 `chapters/{vol}/{ch}/outline.md`。先打开 [SB §7.3](references/formats/chapter.md) 的完整示例：首行是 `# 第{ch}章 outline`，二级标题照表。机读行示例（同节原文）：`- B2 连环：债主的烟盒出现在闸房`、`- 埋 F004：新烟盒`、`- 在场：唐七`、`- 级别：A`。只借格式，换成本章实际内容和登记的 ID。

职责一句话写清推进什么、到章末改变什么；每个场景写明地点锚点、时间感、角色想要什么、离场时什么变了。区分计划在场和仅提及；伏笔写明埋／触／收／弃，支线只触及就别冒填生命周期步骤。卷规划启用区域循环时，读 `bible/volumes/{vol}.md` 自由区按章号交接的步次、新增区域理解、可见收益；把本章对应内容落到现有 `## 本章职责` 或 `## 场景`，不增机读字段。

- **外部事件**：回看前文实际发生的事。若已经连续 `rhythm.external_event_max_gap` 章没有外部事件，本章安排一次从角色当前计划之外来的打断，让它改变行动、选择或代价，不只做一声响。 [模型]
- **支线与互动**：至少触及一条进行中的支线，且至少有一次实际人物互动，不写成通章独白。触及可以很短，如来信让人物改约；不必每次推进正式步骤。不为凑数自行新开支线；没有活跃支线就请作者定。 [模型]
- **小弧线**：默认约三章走完一次铺垫 → 发展 → 高潮或转折。核对本章承担哪一拍，以及卷的核心悬念是有进展、有提醒还是明确留待后章；不要把连续章节都铺成同一种强度。 [模型]
- **日更与钩子**：按卷规划自由区按章号交接的发布日分组，在 `## 日更位置` 填当日第几章、是否末章；承接规划表的钩子级别，在 `## 钩子` 写本章具体落点。末章对照配置的 `daily.last_hook_min` 或 `daily.burst.last_hook_min`（[SB §8](references/formats/config.md)）。缺安排就请作者确认，不自行分组或改级别。 [模型]

本步无额外脚本。作者正在一起推敲时，先发提纲请其确认，再写正文；非实时协作且方向已定时，可按提纲继续。若要偏离卷纲、改动已定设定，或覆盖作者已有文字，先取得同意。

### 4. 写 `v{n}.md`：让变化发生在场景里

读章纲、资料和 `bible/style-guide.md`，按 [SB §7.2](references/formats/chapter.md) 的完整示例写入 `chapters/{vol}/{ch}/v{n}.md`。示例首行为 `# 第12章：闸房的灯`，用全角冒号，章号与目录相同。用下面的段落预算组织正文，不把这些名称写成正文标题：

**开头钩子（200–400 字） → 场景一（主事件） → 场景二（加深冲突或交织支线） → 可选场景三 → 结尾（300–600 字） → 可选下章预告 → 钩子标记。**

两段主要场景可各从 800–1200 字估算，按职责与本书字数目标调整。开头、结尾可以就是首尾场景的一部分；切场、可选下章预告与末行钩子标记照 [SB §7.2](references/formats/chapter.md) 的示例。钩子标记按实际落点写；若落点达不到计划级别，先改写收尾或请作者确认偏差。

第一句从具体物件、动作或台词切入，给出新信息或制造张力；天气不影响剧情就不拿它开场。行动段写「目标 → 阻力 → 意外或代价」，反应段写「反应 → 两难 → 决定」，决定接成下一场的目标。对白默认每 2–3 句插一个有意义的动作或神态。信息只说一遍；对话已说清，旁白只补没说过的含义或后果。删掉替读者下判断的作者总结，压缩无信息、情绪或风险增量的顺利过程。术语第一次出现就用白话说清它是什么、此刻有什么用。

场景、对白和准备章、行动章、收获盘点、交易、借文内资料讲设定的手法查 `fiction-craft`；没装就按本书风格指南和下方参考做最小处理，不为套模板另起一场。若新规则将决定剧情，先请作者拍板；涉及已定设定的改动，先更新权威条目再写依赖它的情节，回写时再核对。

**修订**：新章用 `v1.md`；获准的小修和接写直接改当前稿，不覆盖未经授权的文字。改场序、关键因果或章末落点等大改，按已有最大稿次递增，新开 `v{n+1}.md`，保留旧稿，并更新 `outline.md` 的 `## 定稿` 指向供检查的稿次；已有定稿时，切换前也须获作者同意。稿次指向不是审校通过的证明。本步无额外脚本。

### 5. 先过机检，再审改

确认章纲指向本轮稿次；按章号运行时，脚本检查指定定稿，未指定才取最大稿次。依次运行：

```text
node <本 skill 目录>/scripts/length.mjs <ch>
node <本 skill 目录>/scripts/lint.mjs <ch>
```

`length` 读正文和 `length.*`。`SHORT` 必须补真实场景：给目标增加阻力、让互动改变决定、把后果落到行动上，不补复述或总结。`LONG` 不是失败；明显超过软上限就查是否把两章职责合在一章，先压重复与空转，需要拆章时请作者确认。脚本计数不等于平台计数，也不能判断注水。

`lint` 读正文、配置、作者词表/模式与冻结清单。逐条修 `BLOCK`，判断 `SUGGEST` 的上下文；遇到全书冻结异常，报告并停下，不改冻结正文或重做哈希掩盖问题。退出码 2 是用法、配置或读取等错误，不算通过。

机检过后，把本轮正文、章纲、风格指南、机检结果和改稿授权范围交给 `fiction-review`，走「提问题 → 修改 → 复查」。明确告知是「初稿，待回写」或「返修中，待同步」；此时不把未回写当审校失败，完稿或返修回写后才验收。只在作者授权、确认未冻结且公开状态明确时才允许审校直接改稿；结构性重写交回本 skill。

未安装 `fiction-review` 时，按[轻审与写作备忘](references/draft-pass.md)做章内自查，交稿件、深审待办与未跑的检查，报告「轻审完成，未做编辑式审校」。若审改改变了出场、支线、伏笔或收尾，核对章纲和资料；不要靠删掉章纲条目来绕过既定剧情承诺。改过正文就重跑两项机检；方向或设定争议留给作者，不带着未解决的阻断进入章后沉淀。

### 6. 章后沉淀：按定稿回写，再核对

读定稿、章纲和 `bible/sources.md`，先对照正文和章纲的实际动作，再按 [SB §4.2](references/formats/project.md) 回写；主写表格式查 [SB §6](references/formats/bible.md)。计划没写进正文，就不标成已完成；正文新发生的动作要先如实反映在章纲，若偏离已批准的计划，先找作者确认。

| 主写文件 | 回写什么 |
| --- | --- |
| `bible/appearances.md` | 每章一行，按正文区分在场与提及；返修更新原行，不叠加。 |
| `bible/foreshadows.md`、`bible/subplots.md` | 核对章纲中的实际动作和步骤，写章号与状态；触及不等于推进步骤。伏笔分记读者已知与作者真相，未收写清未来如何回来；新埋不拖到下一章再登记。 |
| `bible/storylines.md`、`bible/character-dynamics.md`、`bible/inventory.md` | 有变化才同步：明暗线实际进展、人物关系/自身弧线、物品消耗、损坏、外借或易手等；不抄剧情流水账。 |
| `bible/timeline.md`、`bible/canon.md` | 记新硬锚、窗口、期限或确认的顺序变动；设定有新裁决或冻结正文有口径冲突时，记作者已拍板的结论。 |
| `bible/characters.md`、`bible/world-rules.md` | 新人物补静态档案，规则有变更新对应细则。 |

把本章留下的衔接点放在章后汇报的「写了什么」里；写下章时再按 [SB §7.4](references/formats/chapter.md) 摘入下章 `resources.md`。不在 `bible/subplots.md` 加非支线 ID 的三级标题（[SB §6.3](references/formats/bible.md)），也不把可能的接法记成已发生。返修若与后续定稿冲突，先请作者裁决。若恰好完卷，按 [SB §7.4](references/formats/chapter.md) 同步 `chapters/{vol}/summary.md` 与 `chapters/{vol}/vol-info.md` 的正文状态；复盘不反推规划。确认的本书写法放到 `bible/style-guide.md`。Markdown 是权威；使用 `fiction-story-db` 的项目可在回写后更新索引，没装则跳过索引。

确认目标章有可读的定稿和章纲，再从本 skill 直接运行：

```text
node <本 skill 目录>/scripts/foreshadow-scan.mjs --at <ch> --only writeback,invalid --fail-on writeback,invalid
```

`--at` 是截止章，不是只查一章。按章号读 `writeback`，按文件与行号读 `invalid`；本章不得有 `writeback` 条目，且本章章纲及相关主写记录不得有 `invalid`。若主写表解析错误使本章是否被正确核对无法判断，也不算通过。退出码 1 表示扫描范围内有发现，不一定属于本章；仅涉及旧章或无关记录的发现单列报告，不擅自改旧章。退出码 2 或没跑、缺稿或缺章纲都不算通过。修正文、章纲或相关主写表后复扫，不能拿旧结果作验收。

还要做[人工回写核对](references/draft-pass.md#人工回写核对)：扫描不会检查正文中漏写进章纲的动作，也不会验证出场、时间、物品等其他回写。脚本缺失或报错时可以用人工清单定位遗漏，但只能报「机检待跑」或「机检故障」，不宣告完工。

## 交付检查

- [ ] 目标章、卷、冻结范围和衔接已核实；有时间推进就已校时。 [模型]
- [ ] 已先定章纲再写，场景有转变，支线触及、互动和外部事件符合节奏条件，实际钩子对得上章纲。 [模型]
- [ ] 需要作者裁决、保护已有稿或实时确认提纲的地方，已取得同意。 [作者]
- [ ] 当前定稿达到字数底线，`lint` 无阻断。 [脚本]
- [ ] 已走完编辑式审校或轻审，未用复述、总结或空转填篇幅。 [模型]
- [ ] 按定稿更新了出场、伏笔、支线与其他有实际变化的主写记录，没把计划当事实。 [模型]
- [ ] 已确认扫描所需的本章定稿、对应章纲及相关主写记录齐备。 [模型]
- [ ] 最新扫描中，本章无 `writeback` 条目，本章章纲及相关主写记录无 `invalid`。 [脚本]

## 产出与汇报

交付 `resources.md`、`outline.md`、本轮 `v{n}.md` 和有改动的主写文件。向作者用四行报告：

1. **写了什么**：卷／章／稿次与路径；本章兑现了什么，下章可从哪个动作、物件或关系接上。
2. **检查**：有效字符数、字数判定、`lint` 阻断数和未采纳的提示、审校或轻审结论、未跑的检查。
3. **回写**：改了哪些主写文件；本章扫描通过、失败（缺项／无效记录）、未覆盖或未跑；无关旧问题单列。本章未通过就报未完。
4. **待定**：需要作者拍板的问题和可选方案；没有就写「无」。
