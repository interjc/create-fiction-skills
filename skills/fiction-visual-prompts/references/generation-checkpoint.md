# 生成前确认：清单通过不等于同意付费

1. **套件只产出提示词。** 本 skill 不调用生成接口，也不代作者点「生成」。即使宿主另有生成工具，也不要把本流程设成自动提交。

2. **一批写完且 `prompt-check` 没有 block，再列预览。** 在书根运行：

   ```sh
   node <本 skill 目录>/scripts/prompt-check.mjs <series> --ep N --json
   ```

   从 `blocks` 选本次待确认的草稿，逐块列键、种类、方言、时长（视频）、参考图张数（`refs` 项数）、长度（`chars`）和涉及的资产。键重复时用文件及行号、帧、方言定位，别把两种方案并成一块。`blocks` 没有资产列表：REF 读 `对象`，帧图取镜内人物、道具加段地点，视频取段内各镜的并集，再按 [SB §9.5](formats/storyboard.md)、[SB §9.7](formats/prompts.md) 解析。附上合计：图片张数（资产参考图和帧图）、视频段数（本批实际要生成的视频块数）和视频总秒数（本批视频块 `seconds` 之和）。不要把作废、已生成、作者提供的外部图或本批不选的备选块算进待生成数。若待生成块的指定图片还未就绪，先列为依赖，不送进当前可执行批次。不估价格；提醒作者自行查看平台当前计费。

3. **等作者明确确认本次清单。** 只有作者明确同意拿这一批去生成，才将清单对应的 `状态` 从草稿改为 `已确认`；作者只同意其中几块，就只改那几块。「继续写」「好的」「分镜定稿了」不等于确认生成。如果不能分辨同意的范围，就保持草稿并请作者指明。

4. **改了就重确认。** 已确认块的正文、负面词、`参考图`（含顺序和实际挂图文件）或其他会改变生成内容的输入变动后，将受影响块退回草稿；重新检查、预览并等待明确确认。资产或分镜变动时顺着依赖检查旧图和下游块，不把旧文件当成新版已出。[模型]

5. **建议一集做完再开下一集。** 按本集的实际依赖先定锚图，再做帧图，最后做分段视频。需要分批时每批单独预览和确认；不要先铺开多集帧图却没做完一集视频。

6. **是否调用宿主另有的工具，由作者当场决定。** 本 skill 只把已确认的块交给作者用于生成，或在成品完成后登记 `文件` 和 `状态：已出`；预览、审批状态和文件存在都不代表本 skill 已执行生成。

7. **作者告知输出存放位置后回填，再验路径。** 对准具体块，按 [SB §9.7](formats/prompts.md) 写入相对剧目录的 `文件`，确认文件存在再标 `状态：已出`，重跑 `node <本 skill 目录>/scripts/prompt-check.mjs <series> --ep N`。找不到文件就不报已出。第一次登记时提醒作者决定产物是否入版本库；别人的副本如果缺图或视频，检查会如实报缺。作者另验实际画面、声音和字迹，脚本只查文件是否存在。
