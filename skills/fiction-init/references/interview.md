# 建书问答：一次问完，按确认值落盘

先把作者已经说过的答案带进问题，不让作者重复输入。发出一条编号消息；说明「可答『全用默认』，或只回要改的编号」。以下是问法、建议默认和去向，不是让模型编造设定的清单。

| 编号 | 同一批里怎么问 | 建议默认 | 为什么问 / 存哪 |
|---|---|---|---|
| 1 | 暂用什么书名？能否用一句话说清谁遇到什么、想得到什么？ | 书名显示「暂未命名」；把已有创意压成一句，不新增人或事件；没有足够信息则梗概「待定」。 | 交接时能认出这本书及其中心冲突。只有作者确认的书名才写 `book.title`；梗概留 `AGENTS.md`，不生成外宣。 |
| 2 | 选一个主包，可再加辅包：仙侠 `xianxia`、都市 `urban`、悬疑 `suspense`、言情 `romance`、科幻 `scifi`、历史 `history`。 | 已有创意明显对应时推荐一个并写出 ID；不明确则暂不选，不凑组合。 | `book.genres` 为有序 ID 列表，主包在前。确认的非空列表才写；不要选不存在的包。使用时找 `fiction-craft`；没装就只记录选择，不自编题材规则。 |
| 3 | 谁是叙述视角？叙述离人物多近，能否进入其他人物内心？ | 第三人称限知、近距离贴当前主角；一场不跳视角，不写当前视角不知的事。 | 人称和「叙述者离人物内心有多近」是两件事，分别写入 `## 本书口径`。作者若选多视角，补一句切换条件。 |
| 4 | 主角规范名、年龄怎么写、两三项核心性格、哪类事绝不会做？ | 名字、核心性格、行为禁区未提供就写「待定」，不代定；年龄先用阶段或年龄段，确有叙事需要再明确。 | 写进 `## 本书口径` 的主角表，给后续写作可执行的边界。把「内向」这类抽象词尽量落实为选择或说话习惯；未确认不建正式人物条目。 |
| 5 | 哪些现实地名、学校、公司不能直接写？精确公历年份／日期要模糊吗？ | 正文和对外文案使用虚构名或泛称，默认不写精确公历年份／日期；没有明确词项先不写词表。 | `lint.desensitize.places`、`.schools`、`.companies` 只记确认的条目，年份按 `lint.desensitize.exact_years` 记录偏离默认的选择。未配词表不等于自动识别真实地名；内部原型留对应档案，精确时间锚留 `bible/timeline.md`。 |
| 6 | 正文最低多少有效字符，超过多少只做提示？是否不设软上限？ | 最低 `2000`，软上限 `5000`；作者选择不设时写 `null`。 | 别按平台算法承诺字符数。改动写 `length.min`、`length.soft_max`；软上限不是失败线。确认数值为整数且上限不低于下限，矛盾时问作者。 |
| 7 | 日常一天几章，最后一章希望至少什么等级的悬念？ | 日常 `2` 章，末章最低 `A`（新信息揭露、悬念加深或强冲突将起）；初建不另排爆更。 | 用于后续排章，不等于发布承诺。只记录作者调整的 `daily.chapters_per_day`、`daily.last_hook_min`。 |
| 8 | 想在哪个平台发？短剧计划做到哪一步：仅小说／分集剧本／分镜／生成提示词？ | 平台「未定」；终点「仅小说」（暂不改编）。 | 平台只作项目意向，终点写入 `## 本书口径` 供工作流判断何时停，不新增配置键。`publish.*` 留给 `fiction-publish` 确认。 |

存放口径时，同一值只有一处持续维护：书名以 `book.title` 为准，`AGENTS.md` 的抬头只是显示；暂名不用写成正式配置。题材、章长、日更和脱敏的机器规则走配置（[SB §8](formats/config.md)），写法和对外尺度走书规。若采用作者修改的文本，在 Markdown 表格内转义竖线、把单元格内换行折成空格；在 JSON 内用正确类型写值。空答案不自动成为书规。

时代和基调可从作者已确认的描述带入；未确定时标「待定」。主角身份和角色秘密的完整档案只在 `bible/characters.md` 维护，主角表只定正文写法。

新书若没有已确定的首卷范围，同批请作者确认临时范围 `1-1`（明确从第 0 章起则 `0-0`）；「全用默认」也可确认这一项。两个卷文件写同一可解析范围（[SB §7.4–§7.5](formats/chapter.md)），卷长由 `fiction-planner` 定。

导入时，用现有口径或手稿中的可核实内容提出建议，标明来源；「全用默认」只适用于建书偏好，不代替对文件映射、采用稿和已发布范围的确认。没有确定的已发布范围不要写 `frozen.ranges`；没有发布过也请作者明确。
