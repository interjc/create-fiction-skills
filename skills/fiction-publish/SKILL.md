# 网文章节发布

> **实验性（experimental）**：平台界面会变。最近实测日期：`待填写（YYYY-MM-DD）`。按当前页面核对，旧按钮名不代表现行流程。

提交作者确认的网文章节或对外文案。逐章用章节管理列表核验并记入本地发布日志；简介则核对作品资料和平台状态。

## 何时用 / 不用

- 用于提交章节或已定稿的简介、定时排期、续接、查发布状态，以及作者授权的改期或分卷。目前只支持番茄小说（`fanqie`）；未支持的平台不套用番茄步骤。
- 仅查状态时只读平台，不新建章节、不保存草稿、不改期、不提交。写章交给 `fiction-chapter`；`publish/blurb.md` 的起草交给 `fiction-planner`，章节和文案审校交给 `fiction-review`。需要的 skill 未安装时，交还现有文件，列明待写、待审和未做的检查，请作者提供确认后的定稿；本 skill 不代写、不代审。

## 开始前

依次读作者项目的 `AGENTS.md`（尤其 `## 本书口径`）、`.fiction/config.json`、`bible/sources.md`。缺失时提示先用 `fiction-init`；未安装则交还现有文件，列出待补资料和因此未做的检查。不要用猜测的发布参数继续。

写或改任何机读文件前，先打开对应的契约摘录，按格式写，不凭印象；本 skill 的发布 CSV 另见下方步骤 2。

只通过宿主提供的浏览器工具操作作者自己已登录的会话。先确认是正确账号和作品，不读取、索要、填写或记录密码、验证码、会话凭据，不代登录、不解验证码、不绕过账号风控或平台限制。登录失效、验证码、风控、未知审核错误或身份不明时，停下并保留现场。没有可用浏览器工具时，只交付本地准备结果，线上状态标为未核验。

## 流程

### 1. 首次确认参数，再确认批次

按 [SB §8](references/formats/config.md)，首次使用时逐项询问并让作者确认以下 `publish.*`，即使文件已有预填值也不视为已确认。汇总获准后写回 `.fiction/config.json` 的 `publish` 对象，保留其他键；把 `confirmed_at` 写为作者实际确认日（`YYYY-MM-DD`），它不是发布日期，也不是发布授权。已有 `confirmed_at` 时，沿用已确认的值，包括符合下表条件且显式保存的 `null`，不要把它、`false` 或 `""` 当缺值。未写入的键、适用条件变化或配置与任务冲突时，先核实再写回，不猜值。

| 键（均在 `publish` 下） | 要确认什么 |
|---|---|
| `platform` | 平台 ID；当前唯一适配的是 `fanqie`，不是自动选择 |
| `daily_word_threshold` | 整数阈值；按平台计数，每天必须严格超过它。不设日阈值时，由作者确认写 `null` |
| `default_time` | 默认定时点 `HH:MM`；同作者核清平台页面使用的时间口径。`scheduled: false` 时可确认写 `null`（不适用） |
| `ai_disclosure` | 按实际使用情况和平台规则申报：`yes` / `no` |
| `detection_mode` | `basic` / `full`；只选平台当前提供且含义一致的方式 |
| `typo_prompt` | 普通错别字提示时 `submit`（允许继续）/ `stop`（停下核稿） |
| `scheduled` | `true` 定时 / `false` 不定时；不能把定时失败自动改成即时发布 |
| `preview_keyword` | 预告关键词原文；明确不填时才写 `""` |
| `log_file` | 发布日志路径；确认是否用契约给出的 `publish/log.csv` 或复用现有路径 |

读 `book.title` 和本书口径。作者确认新书名时，核对 `.fiction/config.json` 的 `book.title` 是否已同步，未同步就请作者确认修正；遇到线上书名不符时核对作品身份，不擅改线上书名。只发简介时转步骤 6，不走章节排期。发布章节时另读目标章的 `chapters/{vol}/{ch}/outline.md`、定稿和 `chapters/{vol}/vol-info.md`，按 [SB §7.1](references/formats/chapter.md) 选稿（优先用 `## 定稿` 指定的稿次，未指定才取最大稿次）。按目录确认卷号，按作者确认的卷名匹配平台。书名、稿次、卷名、章号或文件有冲突、缺稿时，停下核清，不自行替稿或跳章。

小说章节的「定稿」指按 [SB §7.1](references/formats/chapter.md) 选用的稿件文件，作者审批另行确认；分集剧本与分镜的 `状态：定稿` 表示作者已确认。

**授权闸口**：章节批次先列出作品、平台、章号范围及定稿、卷、定时/即时、允许的日期范围与时间、日累计规则，以及是否包含建卷、改期或草稿纠正；简介提交列出作品、要改的字段及获准文案。每个会话在首次不可逆点击（最终确认、发布、落地建卷等）前请作者确认这一批，除非作者已明确预授权该范围和操作；每次点击仍要校验落在授权内，范围或操作变化就先停。配置、旧日志和打开的编辑页都不构成授权。编辑页可能自动保存，作者没授权填稿时，不先写线上内容等发布确认。

### 2. 读日志，恢复到上一处未决

只读写 `publish.log_file` 指定的 CSV。下列是本 skill 新建日志时的表头，不是共享脚本的输入格式。已有日志且列能一一映射时保留原格式；无法对应就先请作者确认，不覆盖旧账。

```csv
作品,章号,标题,源稿路径,分卷,平台章节ID或链接,平台字数,目标发布时间,平台显示发布时间,流程状态,平台状态,核验时间,备注
```

- 新日志用 UTF-8；含逗号、双引号或换行的字段用双引号包裹，字段内双引号写成两个。源稿路径相对书根；分卷记本地卷号和已确认的线上卷名。未知值留空并在备注说明，不能把缺失字数当成零。
- 分开记目标和实际显示的完整日期与时间；核验时间是实际查看列表的时间，不是发布时刻。时间口径已知就注明时区；平台没显示的精度不补造。备注保留异常、恢复动作及改期前值等必要证据，不记登录信息。
- 按平台作品和章号定位同一记录，优先用已记的平台 ID 或链接复核；查到标题、作品身份或章号冲突时不合并。重试、恢复草稿、改期都更新原行，不另起可累计的新行。
- `准备中`：已选定稿、准备填稿；`待核验`：即将点击最终提交或结果未查实；`已核验`：章节管理列表对上身份、卷、时间和相应提交状态；`受阻`：有明确阻碍或核验不符，备注保留看到的事实。平台状态单独记，不用流程状态冒充平台结果。
- 重开会话、断线或作者接管后，先读 CSV，从最后一条 `待核验` 开始，查当前编辑页、章节管理、草稿箱，解决影响本批的未决或受阻记录再继续。没有日志也要先查现有线上章节和草稿再建新章。以重新观察的页面和落盘证据为准，不从聊天里的最后一个章号推下一章。

### 3. 做干净副本，按已核验字数分配日期

对已选源稿运行本地参考计数：

```text
node <本 skill 目录>/scripts/length.mjs "<源稿路径>" --root "<书根>" --json
```

查看 `results[].count`：这是本地有效字符数，只供估算；退出码 1 表示本地字数低于本地阈值，不代表平台判定；退出码 2 先查书根、源稿和配置。命令参数见 `length.mjs --help`。平台显示的当前稿正文字数才进日志和日累计。

只处理待粘贴副本（源稿元素见 [SB §7.2](references/formats/chapter.md)）：移除首行章节标题、所有 HTML 注释（含跨行、作者批注和 `hook`）、独立的 `---` 分隔线以及反引号（保留其中的文字）。保留正文措辞、标点和段落，不改源稿。标题栏只填标题正文，去掉 `第N章：` 或 `第N章:` 前缀，章号另填。若有单独的下章预告且未约定是否随正文发，先问作者。获准随正文发时去掉预告外层的 `*`，保留文字；不随正文发则移除整行。不要把这行自动填入平台预告关键词。

按**平台列表核验到的发布日期**汇总同作品、同平台的已核验提交（含已有排期），跨卷仍累加。草稿、待核验、受阻、本地估算和未查实字数都不计；有未知项则先补查，不宣称达标。

定时且设有日阈值时，从作者确认的首日开始，按章号顺序排。累计 `≤ daily_word_threshold`（包括恰好相等）时，授权内的下一章仍排同日；只有累计 `>` 阈值，才把下一章排到下一天。若 `daily_word_threshold` 已确认为 `null`，定时按作者确认的逐章日期或每日分组安排，只汇总字数，不按字数自动换日、不判达标。非定时按已核验的实际发布日期记账，不自动跨日连发，也不用 `default_time` 假造时刻。

未达标却用完定稿、达到作者确认的每日上限，或下一步日期不可用、会超出授权时，报已核验总量，请作者决定，不凑字、不跳章。设有阈值、总量已知且未达标时，缺口是阈值加一再减总量。

### 4. 一章一循环：填稿 → 检测 → 设置 → 提交 → 核验

读取本平台适配页。每个动作后重读当前页面，只处理实际出现的界面，不盲点弹窗、不顺手改其他作品。

1. **定位**：进入正确作品的已核实列表，查目标章是否已提交或已有草稿；若已有记录先核对，不另建。确认新卷确有需要且已获授权时，先查有无同名卷，再按适配页创建，重新读列表确认只有一个；然后选卷，不重置当天计数。
2. **填稿**：在日志记 `准备中`，绑定当前编辑页，核对作品和卷后填写章号、标题、正文。确认三项齐全，正文首尾与副本一致且没有重复粘贴。读取编辑器当前稿的平台字数，更新同一行；字数缺失、为零或像是旧稿计数时先等页面更新，仍不明就停，不进入检测。
3. **检测和设置**：根据确认的检测方式、错字提示处理和 AI 申报选项操作。核对卷、章号、预告关键词和定时开关。定时时先读日历当前年、月，再按实际差值逐月切换并复读年月，只选目标月的日期；关闭日历后回读完整日期和时间，不能固定点几次箭头。非定时则确认关掉定时，明确这不是排期。
4. **最终点击**：按授权闸口核对作品、章号、标题、卷、目标日期时间（非定时则核对即时提交意图）、检测结果、AI 申报、定时开关和关键词，先将 `待核验` 与目标写入 CSV；写不进去就不点。只点一次最终确认，立即看提示，再等列表更新。报错或超时可能发生在点击之后，先核验再决定下一步，不能重跑整章。
5. **回列表核验**：在正确作品内用章号和标题定位目标行，或用已知平台 ID 定位后复核章号；检查分卷、完整日期时间和状态。找不到先查筛选、排序、分页和搜索，不只看首行。定时记录须对上目标时间，且为 `审核中` 或 `待发布`；若到期后状态为 `已发布`，核对原安排和可见发布时间。提早公开、错卷、错期或证据不足都不是成功；记现状，别再发布一次。即时提交若已显示 `审核中` 但尚无实际发布时间，先记下已受理的证据，等补核发布时间，不拿目标或核验日期代填，也不再次提交。
6. **落盘后继续**：核验成立才记 `已核验`、平台章 ID 或链接（页面可见时）、平台字数、显示时间、平台状态和核验时间，再按步骤 3 的排期规则确定下一章日期。看不到提交证据时保留 `待核验`；明确冲突或阻碍记 `受阻`，按异常指南处理。不在当前章提交结果未明时推进下一章。

平台状态不要混用：**已保存到云端**只是存稿；**审核中**是已提交、未通过审核；**待发布**是等待定时时刻；**已发布**才是已公开。提示“提交成功”不能替代列表核验。

### 5. 按日期收尾并移交

对照授权范围、CSV 和章节管理，检查缺章、重复、待核验、受阻、遗留草稿、错卷、错期；以新核验结果修正记录。按每个已安排的发布日期单独重算总量，改期重算原日和目标日，删重后也重算受影响日期。不用提交操作日、核验日或跨日平均代替。说明库存是否还有定稿、最后安排日期和不足的日期；不要为用完批次而开空卷、写新章或发布范围外稿件。

对核实已进入公开发布范围的新增章节，按 [SB §4.2](references/formats/project.md) 把已公开的章号、对应发布稿路径、日志路径和核验证据交给 `fiction-init` 的「更新冻结清单」模式。本 skill 不改冻结配置、不运行冻结命令；排期提交或审核中不等于已公开。若未安装 `fiction-init`，交还上述资料并标明冻结尚未执行，请作者按顺序完成两步：① 确认章号并更新 `.fiction/config.json` 的 `frozen.ranges`（[SB §8](references/formats/config.md)）；② 在书根通过`fiction-review`、`fiction-chapter` 或 `fiction-init` 附带的 `lint.mjs` 入口运行 `--freeze`，生成或更新 `.fiction/frozen.json`。没有可用入口，待安装 `fiction-init` 后完成第二步，不手写哈希清单。

### 6. 按授权提交已定稿的简介

1. 读 [SB §2](references/formats/project.md) 中的 `publish/blurb.md` 路径约定，取作者确认的准确文案，只提交获准字段。没有定稿就把文件和待办交给 `fiction-planner` 或 `fiction-review`，不边发边改。
2. 在作者已登录的浏览器里核对作品身份，查看作品资料中当前的简介和可编辑字段。没有明确对应的设置入口、发现作者另有改动或作品身份不明时停止，交付文案、待办和未做的检查。
3. 过授权闸口后，将作者确认的原文填入相应字段，复读待提交内容，再点可见的保存或提交一次。回到作品资料核对字段与平台状态，区分已保存、待审核、已公开；超时先查现状，不盲点。单独汇报核验结果，不给简介造章节号或把它计入章节 CSV 和日字数。

## 检查

- [ ] 发布章节时，`length.mjs` 已对所选源稿给出本地有效字符数。[脚本]
- [ ] 作者已确认发布参数和本会话批次，或有覆盖本次操作的预授权；申报如实。[作者]
- [ ] 当前浏览器、账号、作品与任务一致；发章时核对章、卷、稿件和干净副本，未用本地字数替代平台数。[模型]
- [ ] 发章前已落盘待核验状态，提交后按章节列表证据更新原行；发简介则以作品资料核验。存稿不冒充提交。[模型]
- [ ] 发章时按核验到的发布日期逐日复算；启用阈值时，恰等阈值不算达标。缺口、未知和待处理项已列明。[模型]

## 产出

首用或确认修改偏好时更新 `.fiction/config.json`；按需建立或更新 `publish.log_file`，正常发布不改正文或文案源文件。汇报时按日期列章号、已核验的平台总字数、达标情况或「未设阈值」，区分审核中、待发布、已公开，附未核验或受阻章、遗留草稿、最后安排日期及日志路径。简介单独汇报提交的字段和核验状态。只做了本地准备或状态查询就直说，别把它报成已提交。
