## 一、立项一次性问答清单

立项阶段把需要作者拍板的参数整理成**一次批量提问**，每项附可调参考默认；确认后落盘到 `drama/{series}/series.md`（[SB §9.1](formats/drama.md)）和 `.fiction/config.json`（[SB §8](formats/config.md)）。绝不替作者猜测平台规则。创作类数字均为可调默认，机读格式按契约执行。

| 序号 | 提问项 | 参考默认值（可调） | 落盘位置 |
| --- | --- | --- | --- |
| 1 | 英文目录 slug 与中文剧名 | 小写字母数字加连字符，如 `stopped-clock` | 目录 `drama/{series}/` 与 `series.md` 首行 |
| 2 | 来源模式 | 改编 / 原创 | `series.md` `来源` |
| 3 | 单集时长档与总集数 | 常规 90–120 秒、60 / 80 / 100 集 | `series.md` `单集时长`、`总集数` |
| 4 | 付费方案与免费集数 | 首卡点默认配置 `[8, 15]`、占比 `[0.05, 0.25]` | `series.md` `免费集数` + `config.json` `drama.paywall.*` |
| 5 | 目标平台与题材 | 由作者填；题材写法可结合 `fiction-craft` 题材包 | `series.md` `目标平台`、`题材` |
| 6 | 制作形态 | 实拍 / AI 生成视频 / 漫剧 | `series.md` `## 制作形态` |
| 7 | 是否旁白解说主导 | 否（默认以画面和对白推进） | 是则设 `drama.voiceover.os_max` / `vo_max` 为 `null` |
| 8 | 主要人物名单 | 主角 1–5 人，均已在 `characters.md` 建档 | `series.md` `主要人物` |
| 9 | 开场类型 | 动作冲突（默认）；见下方四型说明 | `series.md` `## 开场类型` |

**第 9 问：开场类型怎么选**。开场类型决定每集头几拍靠什么抓人，四型的具体写法与禁忌见分集写作技法（`episode-writing.md`）里按开场类型分的规则表，这里只帮作者选型：

| 开场类型 | 一句话 | 常见适用题材 |
| --- | --- | --- |
| 动作冲突（默认） | 首拍就有人在动手、拦人、抢东西 | 复仇、逆袭、动作任务、强对抗的都市与仙侠 |
| 异常静止 | 首拍先立住一处说不通的字、声音或物件，不靠肢体对抗 | 悬疑、刑侦、规则怪谈、民俗恐怖 |
| 反差旁白 | 一条克制的 VO（或主角 OS）先说，紧接的画面与它唱反调 | 破镜重圆、年代情感、重生、人物侧写 |
| 生活切片 | 一个平时顺手的小动作这回出了岔子 | 温情日常、轻喜剧 |

作者没有偏好时用动作冲突。选定后在 `series.md` 写 `## 开场类型` 小节：一行类型加一句理由（如「异常静止：都市悬疑，第 1 集靠停在三点十分却拧不动的座钟立住不对劲」）。这一节**不被任何脚本读取**，是给后续批次写集、审稿时对齐口径用的；混搭题材以这里的选择为准；个别集确需换型时，在该批写集的汇报里向作者说明理由。选型由作者拍板 `[作者]`，各集开场是否符合所选类型靠模型对照那张规则表判断 `[模型]`。

## 二、时长档位与集数预设表

以下创作数字均为常见可调默认，作者按拟投放平台要求拍板：

| 单集时长（写进 `单集时长`） | 对应制作形态 | 对应 `drama.tiers` 档位 ID | 常见总集数 | 首个付费卡点参考 | 单集内容容量 |
| --- | --- | --- | --- | --- | --- |
| `60-90` | 漫剧 / AI 短集 | `micro`（≤60s）或 `short`（≤120s） | 按平台与故事体量定 | 8–12（或按平台方案调配置） | 1 个紧凑节点 |
| `90-120` | 常规竖屏短剧 | `short`（≤120s） | 60 / 80 / 100 | 60 集 8–11；80 集 10–15；100 集 13–19（或 8–12） | 1 个完整节点（一推一挡或一铺一收） |
| `150-195` | 竖屏长集 / 精品短剧 | `standard`（≤180s）或 `long`（无上限） | 30 / 40 / 50 | 按平台方案与 `free_ratio` 定并核对配置 | 约等于 2 集常规集（2 节点 + 约 50% 中段钩子） |

> `drama-check.mjs` 按 `est_seconds = round(有效字符数 × 60 / drama.chars_per_minute)` 落入 `drama.tiers` 对应档位；单集设置了 `目标时长：T` 时，允许区间自动变为 `[round(0.8T), round(1.2T)]`，否则使用 `series.md` 的 `单集时长` 区间。

## 三、特殊形态与配置冲突处理

选定首个付费卡点集号后，必须立即对照 `.fiction/config.json` 的 `drama.paywall.first_at`（默认 `[8, 15]`）和 `free_ratio`（默认 `[0.05, 0.25]`）。若首卡点落于配置区间之外（例如 100 集选第 16–19 集，或前置卡点选第 3–5 集），必须提醒作者确认并更新对应配置 `[作者]`，否则机检会报 `paywall-position` 阻断或 `paywall-ratio` 建议。

| 形态 | 须调整的 `.fiction/config.json` 键 | `series.md` 与剧本写法 |
| --- | --- | --- |
| **前置卡点短剧**（30–60 集、第 3–5 集进付费；属市场观察、未作平台统一校验） | 作者显式修改 `drama.paywall.first_at`（如 `[3, 5]`），必要时同步调整 `free_ratio` | `免费集数` 填首个带 `<!-- paywall -->` 标记的集号；卡点前仍需先立核心冲突与甜头 |
| **免费剧 / 广告剧**（全剧不设付费卡点） | 把 `drama.paywall.first_at` 设为 `null`：跳过 `paywall-missing` 与 `paywall-ratio`；若剧本仍残留标记，会触发 `paywall-position`（`suggest`），且 `paywall-placement` 与 `paywall-hook` 仍照常检查 | `series.md` 的 `免费集数` 留空；任何分集末尾**不要**写 `<!-- paywall -->` |
| **旁白解说主导剧**（漫剧 / 听书式短剧） | 把 `drama.voiceover.os_max` 和 / 或 `drama.voiceover.vo_max` 设为 `null`；设为 `null` 的那一类（OS 或 VO）在场景 1 开头也不再触发 `voiceover-open` | `## 制作形态` 注明「旁白主导」；`## 开场类型` 多半选反差旁白 |
| **语速偏快 / 偏慢** | 调整 `drama.chars_per_minute`（默认 `250`） | 注意该键同时供下游分镜校验台词时长，修改前告知作者 |

## 四、相关 `.fiction/config.json` 配置键

所有键的权威定义与默认值见 [SB §8](formats/config.md)；缺配置文件时脚本用契约默认值并提示：

| 键 | 默认值 | 用途 |
| --- | --- | --- |
| `drama.chars_per_minute` | `250` | 估算时长用的每分钟字数 |
| `drama.length_level` | `"suggest"` | 单集时长越界时的告警级别（可改为 `"block"`） |
| `drama.tiers` | `micro`(60) / `short`(120) / `standard`(180) / `long`(null) | 估算时长归档表 |
| `drama.max_scenes` | `5` | 单集场景数机检上限（suggest；写作默认更紧） |
| `drama.hook.required` | `true` | 每集必须有 `<!-- hook: X -->` |
| `drama.paywall.first_at` | `[8, 15]` | 首个卡点允许集号区间；`null` 表示不设卡点 |
| `drama.paywall.free_ratio` | `[0.05, 0.25]` | 首卡点集号 ÷ 总集数的允许比例区间 |
| `drama.paywall.hook_min` | `"A"` | 卡点集钩子的最低级别 |
| `drama.dialogue_run_max` | `6` | 同场景连续对白行上限（suggest）；`null` 关闭 |
| `drama.voiceover.os_max` | `2` | 单集 OS 行数上限（suggest）；`null` 关闭 |
| `drama.voiceover.vo_max` | `1` | 单集 VO 行数上限（suggest）；`null` 关闭 |

## 五、原创短剧（模式 B）立项与悬念账更新

只写原创短剧、不同时开发小说时，由本 skill 自己完成短剧核心立项，不强迫作者走 `fiction-planner`。只有当作者还想把创意发展成网文，或想做多版卖点变体与题材定位探索时，才交给 `fiction-planner`。题材共性写法在 `fiction-craft` 已安装时查阅对应题材包。

原创立项先敲定五项并落入 `series.md` 对应位置：

1. **一句话梗概**（写入首部字段 `一句话梗概`）：谁在什么处境下，为了什么紧迫目标，对抗什么阻力。
2. **情绪承诺**（写入 `## 原创立项核心`）：观众追到结尾最核心要兑现的那一口情绪。
3. **主角显性诉求（Want）**（写入 `## 原创立项核心`）：具体可量化或有时限的目标（如「冬至前查清旧闸房失踪真相、保住钟表铺」）。
4. **反派筹码（Stake）**（写入 `## 原创立项核心`）：反派握着什么让主角不得不接招的现实筹码，以及反派同样输不起的东西。
5. **单元切分与 `## 悬念账`**：按总集数和单元步长（默认常规 20–30 集 / 长集 10–15 集）在 `## 单元与节奏规划` 划分单元，并在 `## 悬念账` 表登记每条铺垫的「观众已知」「幕后真相」「埋设集」「计划兑现集」。

**每批写集后的悬念账回写**：原创短剧不写 `bible/foreshadows.md`，每批完稿后按实际埋设、阶段揭示和兑现情况更新 `series.md` 的 `## 悬念账`（补全 `实际兑现集` 与 `状态`），并同步复核本批是否提前泄出 `幕后真相`。

> **无骨架项目的最小前置**：未运行 `fiction-init` 且未安装该 skill 时，本 skill 仅按 [SB §6.2](formats/bible.md)、[SB §6.4](formats/bible.md) 建立 `bible/characters.md` 和空表头的 `bible/foreshadows.md`（否则 `drama-check.mjs` 会以退出码 2 报错），并明确提醒作者补齐其余骨架。

## 六、短剧专属人物建档与机检边界

若改编中新增了小说里没有的人物（例如合并原书配角后的固定线人），按 [SB §6.4](formats/bible.md) 在 `bible/characters.md` 末尾追加独立人物块，**必须标明 `范围：短剧:{series}`**，绝不修改已有共享人物条目：

```markdown
### 阿满

- 身份：钟表铺隔壁修车摊学徒（短剧合并线人）
- 级别：次要
- 别名：小满
- 范围：短剧:stopped-clock
- 读者已知：嘴碎爱凑热闹，消息灵通
- 作者真相：悄悄替债主盯着钟表铺后门动静
- 说话风格：语速快，爱反问，句尾常带“你信不信”
```

**机检与人工核对边界**：`drama-check.mjs` 只核对 `adaptation-map.md` 的 `人物` 列是否在 `bible/characters.md`（含别名）存在；它**不核验** `series.md` 的 `主要人物`、人物 `范围` 字段、映射表与剧本实际出场是否一致，也**不拦截**分集 `状态` 拼错（如误写 `已定稿` 会被下游当成未知状态）。这四项必须由模型人工核对 `[模型]`，定稿决策由作者拍板 `[作者]`。

## 七、`series.md` 自由小节约定

[SB §9.1](formats/drama.md) 允许在固定字段之后放自由小节，本 skill 使用以下小节名便于跨批次与下游查找：

- `## 制作形态`：实拍 / AI 生成视频 / 漫剧，以及是否旁白主导。
- `## 原创立项核心`（仅模式 B 原创剧）：情绪承诺、主角显性诉求、反派筹码。
- `## 开场类型`：动作冲突 / 异常静止 / 反差旁白 / 生活切片之一，一行类型加理由；脚本不读。
- `## 人物弧`：核心人物的起点 → 关键代价 → 终点变化。
- `## 单元与节奏规划`：单元起止、四幕节点、重点集清单、各级付费卡点集号，写在本节，不进映射表。
- `## 改编口径`：仅短剧生效的砍线、并人、改序和局部口径，不回写小说 bible。
- `## 合规注意`：最近核对日期与待关注项，一律写明「以平台与主管部门官方现行文本为准」。
- `## 悬念账`（仅模式 B 原创剧）：追踪原创剧的悬念埋设、揭示与兑现。
