# 伏笔与支线

## 伏笔：埋下时就知道怎样回来

1. **计划**：在 `bible/foreshadows.md` 按 [SB §6.2](formats/bible.md) 登记。分开写「读者已知」（现在看到什么、会怎样理解）和「作者真相」（实际原因、长线意义）。同时写「未来出现方式」：在哪类场景，经哪个物件、动作或人物、由谁揭开。可暂不定回收章，但回归方式不能只写“以后揭晓”。
2. **埋设**：先说出这个细节当下在做什么：例如解决眼前麻烦、交代关系，或改变角色的一次判断。把未来真相拿掉，再读一遍：细节仍然有用、像场景自然长出来的，才放进去。不另起一场只为交付线索。确定正文已埋，立即回写真实埋设章和状态；别等到卷末补记。
3. **触及**：换角度唤起记忆，如换人物看到后果、让旧物在新场景发挥另一项用途。只提醒就记触及章，不标成已揭；揭了一层才标部分揭示，同步更新「读者已知」，保留未揭真相和下一次回归方式。
4. **回收**：回读埋设场景。先用一句短回忆或重现一个可辨认的动作、声音、物件，让读者想起当时发生了什么；然后用本场景的新证据给出不同诠释。不是重讲旧场景，也不是再报一次谜面。每章优先收一条，最多两条；其余留给后章。正文完整回答后，才标已回收、填实际回收章，并更新「读者已知」。
5. **改期 / 放弃**：先看读者是否已把它当成承诺、有哪些支线和章节依赖，列清代价。改期要有新窗口、可执行的回归方式、必要的中间触及；放弃要在备注写理由，说明读者已见线索是否需在后文自然消化。作者决定是否放弃或改期，挂靠 A 级线的条目不能因为逾期就自行顺延或删掉。保留原记录，不删除已公开的痕迹。

## 逐条处理扫描结果

用 `foreshadow-scan.mjs` 的文件与行号定位原表，回读埋设处及最近一次触及，再看当前卷计划。到期和沉睡可同时命中，把它们当作同一条的多个理由，不排两遍。

| 类别 | 怎么读，怎么处理 |
|---|---|
| `due` / `overdue` | 到期覆盖窗口前预警期、计划回收窗口本身及窗口后的宽限（含 `start - due_window` 与 `end + overdue_grace` 两端）；超过后者才算逾期。原场景及前置证据到位、本章又有空间，就建议收；证据还差一层，就建议有作用的触及，并评估是否须改期。默认预警提前 3 章，逾期宽限 0 章，以 [SB §8](formats/config.md) 的 `foreshadow.due_window`、`foreshadow.overdue_grace` 为准。 |
| `dormant` | 距最近埋设或触及达到 `foreshadow.dormant_after`（默认 30 章）；即便没定回收章也会报。先问还有没有叙事价值；需要留就设计有新信息的触及，再判断回收、改期或提请放弃。不为清警报重复一句提醒。 |
| `plant_due` | 已到计划埋设章但仍标计划中。核对定稿是否确实已埋；没埋就看有无自然入口，不能把预计出现记为发生。 |
| `writeback` / `invalid` | 先对照报告指出的章纲动作、实际正文及主表。获准后按实际动作修主表；章纲与正文不同，把未冻结章的差异交给 `fiction-chapter` 核准章纲，冻结章的差异另报。有结构或字段问题就打开对应摘录修，不填假章号、假回归方式。 |

查询结果不是写作命令。对每个到期、逾期或沉睡条目说清：**读者目前知道什么 → 本章能做什么 → 建议做什么及原因 → 哪份文件会变**。回收或触及的建议交给 `fiction-chapter` 落进未冻结章的提纲，写成后再记实际章；改期获准后才更新伏笔表的计划，影响卷规划时交 `fiction-planner` 同步。

## 支线：先挂主线，再排六步

一条支线是有自己进展、又能改变主线的旁路。按 [SB §6.3](formats/bible.md) 在 `bible/subplots.md` 分级：A 大支线直接推动或挑战主线、牵涉核心人物，通常跨三卷以上；B 中支线服务当前卷、给主线增加阻力或厚度，通常一到两卷；C 小支线在一到三章内完成，用来调节节奏或补世界的一角。

**删除测试**：填「挂靠主线」时说清删掉此线，主线哪一次选择、资源得失、关系或事件结果会不一样。若答案是“都一样，只少一点热闹”，重挂到能产生后果的节点，或提请作者砍线。支线只记推进，伏笔细节引用 F-ID，不重复维护。

| 步骤 | 给它一个看得见的作用 |
|---|---|
| ① 种因 | 种子先解决当下场景的问题，不能只为远期存在。 |
| ② 提醒 | 换角度让种子再出现；距种因默认 5–15 章（`subplot.remind_gap`）。 |
| ③ 连环 | 让它和另一条线或主线在同一事件中碰上，读者能看出关联。 |
| ④ 误导 | 用读者已见的事实支持一个合理但错误的解释，不靠旁白撒谎。 |
| ⑤ 小收 | 真正回答表层问题，再显出深层问题，不只换一句谜面。 |
| ⑥ 大收 | 回答这条线的核心问题并让后果落到主线；A/B 级从种因到大收默认不超过 100 章（`subplot.max_span`）。 |

A/B 按六步走，C 可只做种因与大收。分别写计划章和实际章；有实质推进才填实际章，一句提醒不自动算完成一个新步骤。

章后有可用的衔接点，记在章后汇报的「写了什么」，注明能推进哪条线或下次可做什么；写下章时由 `fiction-chapter` 按 [SB §7.4](formats/chapter.md) 摘入下章 `resources.md`。不把候选动作记成已发生，也不在 `bible/subplots.md` 新增非支线 ID 的三级标题（[SB §6.3](formats/bible.md)）。

- `stalled`：进行中、尚未大收，距最近完成步骤达到 `subplot.stall_after`（默认 20 章）。检查能否把下一步接进主线事件；不能就提议经确认休眠或调整计划，不虚填进度。
- `span`：A/B 已种因、尚未大收，已到 `max_span`。核查是否把多个承诺挤成一个大收；必要时提议按完整承诺拆成有独立收束的阶段，不能把此线改名重开来逃避提醒。跨卷不等于可以无限拖延；与项目跨度冲突时列出方案请作者定。
- `remind_gap`：种因和提醒都实际完成，但间隔偏离设定范围。回读两处再判断是节奏有意为之，还是需要在后续补桥；不倒改冻结章。

没有本书特例时，试着每章至少带到一条活跃支线，一句话也可；可用约三章做完一轮铺垫、发展、转折。安静段落优先推进现有 B 线或插入一个可收的 C 线、一个有后果的外部变化；连续安静章的打断间隔以 `rhythm.external_event_max_gap`（默认 2）为参考。这些是排查节奏的办法，不是脚本结论。

## 大钩子链：一卷回答一个问题，并把读者交给下一卷

在 `bible/volumes/{vol}.md` 查本卷贯穿始终的核心悬念、种子与预定收束章，并对照下一卷拟开的核心问题。默认在本卷过半前让下一卷种子已经出现在正文；在本卷收束时先兑现本卷承诺，再让旧答案打开新问题，别到最后一页临时抛出一个无因的新谜团。章尾钩子可以帮忙交接，但不替代全卷悬念。

保留卷规划里的安排，支线和伏笔各到自己的主表记录实际发生；卷末核对「本卷回答了什么、下一卷凭哪一场已埋的戏接手」。关键事件后，查直接参与、间接知情、仍不知情、远端影响四圈；有新后果就找它挂回哪条主线或支线。
