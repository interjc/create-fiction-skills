## 一、两层把关与 `usable_from` 优先级

小说档案把悬念信息拆成「读者已知」与「作者真相」（[SB §1](formats/project.md)）。到了分镜阶段，画面比文字更容易无意泄底，防剧透分两层把关（[SB §9.9](formats/storyboard.md)）：

1. **脚本硬拦截 `[脚本]`**：`storyboard-check.mjs` 按以下**严格优先级**计算每个资产条目的最早入画集 `usable_from`：
   - 若条目显式填了 `揭示集`（正整数），**直接取 `揭示集`**，不再看 `揭示伏笔`；
   - 否则若填了 `揭示伏笔`（F-ID 列表），取这些伏笔在 `adaptation-map.md` 中「收」所在集的**最大值**；**只要其中任意一条在映射表里还没有「收」的行，该条目即为「尚不可用」**；
   - 两者都未填时，`usable_from = 1`。
   第 `e` 集分镜在 `人物`、`道具` 或段 `地点`（按 [SB §9.5](formats/storyboard.md) 解析后）引用了 `usable_from > e` 或「尚不可用」的条目，脚本直接报 `sb-spoiler` 阻断。
2. **模型逐镜把关 `[模型]`**：脚本只查资产键引用，读不懂自由文本有没有换说法把真相写出来。因此必须对照最新简报（及原创剧的 `## 悬念账`），**逐镜并连同段级 `站位`、`环境声`、`配乐` 以及镜级 `画面`、`声音`、`备注`** 全部核对一遍。

## 二、开工前读懂 `--brief`（含刷新与原创剧悬念账）

画第 `N` 集分镜前运行：

```text
node <本 skill 目录>/scripts/storyboard-check.mjs <series> --ep <N> --brief
```

**刷新规则**：只要你在步骤 2 往 `visual/assets.md` 新增或修改了任何 `揭示伏笔` / `揭示集`，**必须重新跑一次 `--brief`**——新增的 `揭示伏笔` 会把此前不在 `adaptation-map.md` 里的伏笔新纳入简报，沿用旧简报会漏查。

准确理解三节数据的边界，不夸大脚本覆盖范围：

| 信息来源 | 实际覆盖范围 | 核对动作 |
| --- | --- | --- |
| `## 本集不得画出的真相`（简报） | 出现在 `adaptation-map.md` 任一行**或**任一资产 `揭示伏笔` 里的 F-ID，去掉「收」或「弃」早于本集的条目 | 1. 未到回收集：全集只能画 `读者已知` 那一面，段级与镜级自由文本都不得暗藏 `作者真相`。<br>2. 标有 **「本集揭示」** 的伏笔：先在剧本里定位真正揭晓的场次和台词，**揭示点之前的镜头仍按未揭示守住**，揭示镜及之后才可画出真相。 |
| `## 人物秘密`（简报） | 仅涵盖**本集映射表 `人物` 列**与 `series.md` **`主要人物`** 中在 `bible/characters.md` 填了 `作者真相` 者 | 脚本不知道秘密在哪集揭开；逐人对照本集剧本与前集映射，未揭晓前绝不通过神情特写、随身暗物或背景物件拍漏隐藏身份。若映射缺行会漏人，所以开工前必须先补齐映射行。 |
| `## 尚不可用的资产`（简报） | `usable_from > N` 或「尚不可用」的资产条目 | 本集分镜不得引用这些键，也不得不挂键却在 `画面` 里偷画其关键特征。 |
| `series.md` 的 `## 悬念账`（**原创剧必读 `[模型]`**） | `来源：原创` 的剧往往没有小说伏笔表，原创悬念记在 `series.md` 的 `## 悬念账` 中，**脚本不会扫描它** | 原创剧开工前手工打开 `drama/{series}/series.md` 读 `## 悬念账`，把本集尚未揭晓的悬念一并列入逐镜核对清单。 |

## 三、四种常用视觉藏法

当剧情要求神秘人物或关键道具提前出场制造悬念、但又不能露出真容或真相时，优先用下面四种手法藏住：

1. **背影与后斜侧**：机位落在人物身后或侧后方，只给肩背轮廓、衣领或行走动态，不切正面与正侧脸。
2. **前景遮挡**：利用房间原有门框、毛玻璃门、柜台边缘、桌沿或另一人的肩膀挡住关键部位（例如隔着毛玻璃只见人影轮廓，或木相框立在柜台深处只露正面边角）。
3. **逆光与暗区剪影**：顺着场景原有光源（窗光、路灯、门缝光）把人物摆进背光暗区，形成剪影轮廓；不为了藏人凭空改动全场的实景主光方向。
4. **局部取景**：用特写或大特写只拍鞋尖、按在门把上的手、袖口或物件的局部非泄底面，绕开会暴露身份或字样的部位。

> 轮到正式揭示的那一镜时反向检查构图：确保前景杂物或阴影没有把该让观众看清的证物或正脸挡死。

## 四、遮挡变体与继承字段交接

**哪怕只提前入画一次，只要对象受门禁限制且可能泄底，也必须做遮挡处理**，不要因只出一镜就放宽。

建遮挡变体时要牢记 [SB §9.4](formats/storyboard.md) 与 [SB §9.9](formats/storyboard.md) 的两条继承机制：

1. **本体只登记可见外观**：`visual/assets.md` 只写画得出来的视觉特征（不把抽象剧情真相抄进 `外观`）。
   - 例 1（道具不同面）：本体 `旧照片`（正面普通合影，无揭示限制）第 1 集即可入画；变体 `旧照片@背面` 写背面手写日期并挂 `- 揭示伏笔：F003`。揭示前只用 `旧照片`。
   - 例 2（整个人物在揭晓前不能露真容）：本体 `神秘访客` 写可见正脸外观并挂 `- 揭示伏笔：F005`（或 `- 揭示集：12`）；为了提前拍他走过巷口，另建遮挡变体 `神秘访客@黑衣背影`，`外观` 只写背影可见的黑色长风衣与压低帽檐，并加 `- 揭示集：1` 覆盖入画门槛。
2. **`揭示集：1` 只解除入画门槛，不清除其他继承字段**：变体默认继承本体的全部字段。如果下游 `fiction-visual-prompts` 日后给受门禁的本体加上了泄底的 `锁定词`（例如“左颊月牙疤”），遮挡变体若未覆盖 `锁定词`，就会把这把锁继承过去，在下游触发 `pr-lock` 或 `pr-spoiler` 冲突；同理，若给早期镜头错挂了本体的正面参考图，也会直接画穿真容。
3. **本 skill 的交接动作**（本 skill 不写 `锁定词`）：建好 `揭示集：1` 的遮挡变体后，在汇报的「资产与连戏变动」里明确注明交给 `fiction-visual-prompts`：
   - 该变体属于防剧透遮挡版，下游若给本体补写涉密 `锁定词`，须在该遮挡变体上用空值 `- 锁定词：`（或非泄底锁定词）显式覆盖；
   - 揭示集之前的帧图与视频提示词**严禁挂载本体参考图**，只能挂遮挡变体自己的参考图。

## 五、高风险边界与何时必须问作者

遇到以下情况不要替作者拍板，标出存疑并停下来问作者：

- **人物秘密或原创悬念账的揭示时机不明**：剧本台词带了暗示但未挑明，不确定画面上该完全藏住还是留一丝可疑细节。
- **道具能否露半边细节**：例如刻字道具在正式显字前，要不要先拍到铜锈下隐约有一道划痕。
- **剧本本身已经写透真相**：如果剧本动作行或台词已经把未收伏笔写穿（分镜怎么藏都绕不开），停下请作者决定是回 `fiction-short-drama` 改剧本，还是调整伏笔回收集。
